# Desktop architecture and integration boundary

The Electron main process owns `JobService`, `SetupService`, the model catalog, native pickers, root handles, job state, review evidence, and file opening. The sandboxed preload exposes fixed, schema-validated operations. The renderer has no Node, shell, arbitrary filesystem, or MCP command access. IPC checks the owning window and main frame, validates requests and responses, and forwards only validated job events.

The side-effect-free `@ne-psd/desktop/bootstrap` export provides `startDesktop` for A's production composition entry; `main/index.ts` remains D's explicit development executable. `startDesktop` selects production mode before service composition whenever Electron is packaged. With no injected production services it fails closed. Explicit unpackaged development fake mode uses `NODE_ENV=development` and `NE_PSD_DEV_FAKE=1`; the main process passes a dedicated preload argument for fake-only controls. No production job can be selected by a renderer flag, query string, or fake corpus channel.

A's production entry must inject a complete `DesktopServices` object: real frozen `JobService` and `SetupService`; authoritative `ModelOption[]` with exact artifact/runtime, capacity, and capability evidence; `reviewPolicySha256`; `previews(profile)` yielding three actual image bytes as data URLs with their SHA-256 and profile binding; and `prepareLinkedCopy` when linked Photoshop dependencies exist. It must also supply the optional `JobEvidenceAdapter` with current-job `EvidenceBundleManifest` plus committed-output record, and `JobDetailAdapter` with durable `ReviewDecision`/manifest records if historical verdicts and diagnostics are to appear. The desktop verifies all supplied bytes and bindings, but it cannot create live Photoshop/model qualification. Missing production adapters stay unavailable. The injected job service is responsible for persistence, transaction recovery, and the qualified runtime controller. Packaged-resource verification occurs before the window; `launchPackagedMcp` is available but the real service adapter must invoke it with the verified bundle and own its lifecycle.

`SetupController` binds template/source hashes, qualified selectors, fit/output policy, copied working template, decoded previews, candidate/profile persistence, exact model qualification and current assets to an interactive `JobSpec`. `JobSessionController` persists recent IDs, rehydrates snapshots, checks current review manifests and committed records, and pauses active jobs before close. A blocked/failed or ambiguous Photoshop state without trusted quiescence proof keeps the app open. `JobDetailAdapter` exposes only bounded, manifest-backed evidence digests and redacted diagnostic summaries. Synthetic fake records are labeled; a fake fixture is never a committed output.

The renderer's `JobStore` uses one subscription, validates event order, reconnects through authoritative snapshots, and displays at most 50 asset rows. Frozen `JobSnapshot` has no durable event cursor or phase-start timestamps. Reconnect can display current state but cannot prove a gap-free historical stream or calculate trustworthy elapsed phase time; A must provide these fields through a coordinated contract change or a separate trusted adapter before claiming those features. No scheduler is part of this release.

# Template setup

The desktop setup flow keeps PSD, input and output selection in the main process. Renderer state contains only portable root-relative references, digests, frozen selectors and service-returned qualification data. Synthetic previews are labelled and never qualify a template.

Qualification requires live inspection, capabilities, structural selectors, exactly three distinct variant groups, supported fit mode, output policy and linked-dependency isolation evidence. Source, selector, fit, output or backend changes invalidate the previous profile. Unqualified candidates cannot be passed to `JobService.start`.

The synthetic shell displays `cover`, `contain` and `stretch`; unsupported modes remain visible and disabled with the required explanation. The exact template path is not stored in portable setup state.

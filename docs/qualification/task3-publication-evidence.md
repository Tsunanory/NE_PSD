# Task 3 publication evidence

Status: filesystem boundary, SQLite intent, restart reconciliation, pending-review persistence, and one-shot visual attestation are implemented and locally verified on macOS. No Windows durability claim is made.

The publication boundary requires a prepared, persisted transaction intent and a passed automated review-gate result. It binds the job, asset, attempt, transaction key, output-root identity, manifest digest, decision digest, review ID, policy digest, and model provenance digest. It checks the sealed bundle, rejects unlisted files and destination conflicts, writes a canonical committed manifest, syncs staged files and directories, rechecks the bundle and root, then renames the whole directory within one filesystem. A process crash after rename but before SQLite completion leaves a directory that can be validated against the durable intent. Reconciliation validates every listed file, rejects extra files, and moves corrupt job-owned directories into a controlled quarantine without deleting evidence.

Verification on 2026-09-30: the four focused publication, reconciliation, pending-review, and visual-attestation store suites passed 24 tests. The latest full core working-tree run passed 131 tests. Core typecheck and build passed before a concurrent JobService rewrite removed its source file; the latest typecheck is blocked by that missing import, outside this packet. A reopened SQLite database completed a rename-before-DB crash exactly once. A crash after moving corrupt output to deterministic quarantine was also reconciled without a publication row. Pending review retains the exact V2 request, evidence, manifest, and QA record; changed selected reviewer and staging bindings are rejected. The one-shot visual request and receipt survive reopening, accept identical replay, and reject conflicting or stale submissions. Persisted review session IDs reject reuse across restart. These results depend on shared contract changes awaiting their separate commit. Tests use temporary local directories and injected byte changes. They do not prove Windows Photoshop or model compatibility. Manual attestation publication remains a separate integration packet.

Directory sync is attempted and required on macOS. Windows may reject directory handles or directory sync; those specific unsupported errors are tolerated. File sync and same-volume rename still run, but Windows power-loss durability must be tested on the release host. Node's rename API has no portable no-replace option; the code checks destination absence immediately before rename. Cross-process writers outside the repository's single transaction owner could race this check, so publication ownership must remain serialized.

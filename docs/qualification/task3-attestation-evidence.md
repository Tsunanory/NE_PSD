# Task 3 manual visual attestation

Status: manual/test-mode preparation and acceptance validation implemented on staged image bytes. Durable repository consumption and C's V2 manifest migration remain integration dependencies. This is not an automated vision-review qualification.

`prepareVisualReviewRequest` verifies the current interactive job and sealed evidence, including three outputs, qualified per-variant references, and derived detail crops. It creates a transparent PNG contact sheet with all nine image panels at native pixel size and no overlays; an accompanying layout gives each panel's position. The contact sheet enters the pre-attestation manifest as `imageInput`. A random one-shot `VisualReviewRequest` binds job, asset, attempt, source/profile/tool/policy hashes, exact three artifacts, contact-sheet hash, and the canonical pre-attestation content digest. The digest excludes the attestation file to avoid a cycle.

`acceptVisualAttestation` accepts only request ID, decision and notes from submission. The operator identity and clock come from trusted main composition. It rehashes the full content manifest and checks current attempt, selected planner/reviewer profile digests, policy, source, output tuple, contact sheet, request ID and expiry. Identical stored submissions return the same attestation; changed, stale, forged-actor and drifted submissions fail. Reject never authorizes publication. It returns canonical V1 attestation bytes for durable storage; `sealAttestedManifest` requires the trusted consumed SQLite receipt, then adds the stored attestation file and rehashes the final closed packet only after approval.

The canonical `HumanVisualAttestationV1Schema` is prepared in shared contracts but uncommitted pending owner approval of the shared-contract packet. It embeds the strict `VisualReviewRequest` and records decision, notes, trusted operator identity and acceptance/expiry times. Its own file path and SHA-256 remain only in the trusted SQLite receipt. The repository owner is implementing atomic one-shot request/receipt persistence; until that lands, these pure validation functions are not an exposed `JobService` flow. C's existing trusted-attestation reader expects the receipt and recomputes the pre-attestation digest from the final manifest minus the human-attestation file.

Focused tests use real temporary PNGs. They verify pixel preservation in every panel, one-shot binding, identical/conflicting replay, actor spoofing, stale attempt, changed output bytes, rejected decision and final-manifest sealing. No live operator, Photoshop, Windows, or model visual evidence was exercised.

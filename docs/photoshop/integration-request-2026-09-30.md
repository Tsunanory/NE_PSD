## 1. One installation lock, with positive release proof

**Current mismatch.** A's `RenderRunner` acquires a separate `PhotoshopLease`, then B's `PhotoshopBackend.render` acquires `SessionLock` (`packages/core/src/runner.ts:21–31`; `packages/photoshop/src/backend.ts:264–268`). A's lease type has only job/process diagnostics and an optional `safeToRelease` callback (`packages/core/src/backend-serialization.ts:1–2`). B's OS-visible owner record has installation digest/path, host/PID/process start, operation and ownership token, journal path, in-flight and unsettled counts, unknown-mutation flag, and document reconciliation state (`packages/photoshop/src/session-lock.ts:10–25`). The design assigns the only installation lock to B (`docs/superpowers/specs/2026-09-21-ne-psd-design.md:220`). A's in-memory serialization can remain as an admission guard, but it cannot authorize lock release.

**Preferred minimal migration.** Remove A's installation `PhotoshopLease` acquisition/release from `RenderRunner`. B's `SessionLock` is the sole OS-visible installation authority for render, qualify, inspect, and recovery. A calls `PhotoshopBackend.render` once and treats its typed ambiguous-state error as blocked; it does not clear a block merely because a transport promise settles. B returns `recover(...).safe: true` only after checking the persisted owner/journal identity, zero in-flight and unsettled operations, no unknown mutation, and reconciled job-owned documents. B retains the lock for timeout after save, paused export, dead MCP child with outstanding mutation, failed persistence, and stale owner until explicit read-only reconciliation proves quiescence. Cancellation between variants retains the lock only while operation state or owned-document cleanup remains unproven; cancellation at a safe boundary may release it after positive quiescence and cleanup proof. No heartbeat age, dead PID, caller `finally`, or client-side timeout establishes safety. Ordinary acquisition never steals stale ownership; `adoptRecovery` remains an explicit recovery-only path (`session-lock.ts:87–180,183–225`). A must not implement another installation mutex in production composition.

**Shared interface choice.** Keep the existing `PhotoshopBackend.render/recover` boundary if A can derive all durable state from B's typed result and evidence. A may request one narrow recovery-proof result (installation/owner/journal identity, reconciled status, evidence paths) if it must verify that `safe: true` corresponds to the retained lock. Do not add a broad second lease interface unless composition proves B's lock cannot be the single owner. A and B must jointly review this choice before either removes the current guard. B's current `recover` result (`packages/contracts/src/services.ts:21–27`) is too terse to prove the journal itself; B must produce/validate the proof, not trust the boolean returned by an adapter.

**Migration/tests.** A changes `runner.ts`, `backend-serialization.ts`, recovery handling and focused core/integration tests; B exposes any required narrow proof from `SessionLock`/`OperationJournal` through `PhotoshopBackend` and tests persisted-journal identity. Test two processes sharing one installation; stale owner with mismatched start identity; dead MCP child and unresolved mutation; timeout just after save; paused export; cancellation between variants; late reply; and read-only recovery followed by positive release. Assert no second job enters while state is unknown and no cleanup, replay, or same-name re-export occurs. Fake tests establish protocol behavior only; real Photoshop and Windows remain separate gates.

## 2. Job-owned source and linked dependency handoff

**Current mismatch.** `RenderRequestSchema` contains `asset`, `profile`, `attempt`, and absolute `stagingDirectory`, but no owned source, dependency closure, or scratch ownership (`packages/contracts/src/domain.ts:120–128`). A optionally copies one validated source into an attempt workspace, then sends B the original `asset.source` (`packages/core/src/runner.ts:11,23–28`; `packages/core/src/attempt-workspace.ts:23–34`). B's working-copy code independently discovers and copies linked resources, records original/copy paths and hashes, and checks relinked closure (`packages/photoshop/src/working-copy.ts:76–92,221–321`). These two copies currently have no reviewed handoff. The design requires unchanged originals and job-owned copies, including linked dependencies (`docs/superpowers/specs/2026-09-21-ne-psd-design.md:214,220,242`).

**Proposed schema, for A to own.** Add one strict `ownedInput` object to `RenderRequestSchema`: an attempt-root-relative source copy path with source `FileRef`, byte count and SHA-256; an attempt-root-relative scratch directory; and a dependency manifest of stable identities, original `FileRef`/digest/bytes, owned relative copy path/digest/bytes, and link kind. Keep `stagingDirectory` as the only absolute request path. All owned paths resolve under the canonical attempt root using A's path API. The same manifest must be emitted as digest-bound evidence so A can reread copied bytes and confirm cleanup is limited to owned paths. A's asset identity and source digest remain those of the immutable original. B must render from the declared owned source copy, never silently reopen `asset.source`; B must verify copied bytes and the full linked closure before mutation. A and B must agree which side creates the dependency manifest before it is marked required: B already has linkage discovery, while A must verify the resulting paths/digests. A narrow B `prepareOwnedInput` result before render is an acceptable equivalent if adding all linkage fields to `RenderRequest` would force A to parse PSDs. The result must be validated before any Photoshop mutation and then bound to the render request/attempt identity.

**Migration/tests.** A updates `packages/contracts/src/domain.ts`, generated JSON Schema, fixtures, `RenderRunner`, attempt workspace, and all fake consumers in one coordinated commit; B incorporates that commit and removes any duplicate local request type or unchecked cast. Tests must prove a valid source plus nested linked dependencies are copied and byte-verified; missing/tampered dependency, symlink escape, wrong attempt/ownership identity, different volume, and unexpected original mutation block before rendering. Relink/embed may change a job-owned parent copy, but its actual post bytes and link closure must be checked; a boolean callback alone is insufficient (`working-copy.ts:288–310`). Cleanup removes only manifest-listed job-owned paths after B proves quiescence. A and B record source/dependency digests and both ownership roots in evidence. This proposal needs versioned schema migration and consumer agreement; no shared schema was changed here.

Mac unit tests may prove lexical cases and argv construction, not actual Windows filesystem, Photoshop, or packaged runtime behavior.

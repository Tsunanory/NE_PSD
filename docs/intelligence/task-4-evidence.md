# C4 implementation evidence

The C4 reviewer implementation validates sealed evidence and actual decoded images before model invocation, preflights token and image limits, uses fresh sessions, and validates strict model decisions after a second byte/state check. The C4 tests use generated real PNG bytes. They cover three separate output variants, all ten image-channel attachments, complete fifteen-check decisions, manual consumed attestation, malformed or missing variant/check sets, wrong session/attempt/digest/provenance/reference, severe finding with aggregate pass, unsupported correction, failed deterministic evidence, corrupt image, image count and context overflow with zero model calls, changed image bytes after inference and renamed bundle root.

Focused verification on pinned Node 22.23.2: four suites, 55 tests passed (`runtime-review`, `visual-inputs`, `evidence-integrity`, `image-quality`). Intelligence build passed. A full intelligence run during concurrent C5 fixture regeneration produced 195 passes and two failures: a temporary C5 descriptor digest mismatch while regeneration was in progress, and one C5 local-transport malformed-profile assertion. The transport assertion was corrected; the C5 fixture owner is rerunning after regeneration. Neither failure is evidence of a live Windows/Photoshop/model gate.

Known release gates: the V2 shared review union and manifest proof roles are not yet adopted; A's persisted V2 reader is absent; exact Qwen/reviewer runtime, Windows 11 x64, Photoshop and visual acceptance remain unqualified. V1 synthetic pass is not live compatibility.

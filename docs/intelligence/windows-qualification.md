# Windows model qualification

The operator runtime bridge must sample resources about every 5 seconds from `beginMeasurement()` through the end of the corpus. Samples must have strictly increasing timestamps, cover corpus start and end within 5 seconds, and leave no gap above 10 seconds. `measure()` returns the collected samples after the corpus ends, including one near its end. Sparse or duplicate-start observations block qualification. Finite sampling can miss shorter spikes; retain native peak and paging counters when available.

The foreground CLI accepts an explicitly selected artifact manifest, fixed corpus, repetition count 3, expected platform, and report path. A separate reviewer manifest is required when reviewer weights differ. Example:

```sh
npm run qualify:model --workspace @ne-psd/intelligence -- --profile docs/intelligence/qualification/requested-local.json --expected-platform win32 --corpus tests/intelligence/fixtures/acceptance-corpus.json --repetitions 3 --with-photoshop --runtime-adapter qualified-runtime-bridge --report docs/intelligence/qualification/windows-local-report.json
```

`--runtime-adapter qualified-runtime-bridge` loads only the packaged bridge at `transport/qualified-runtime-bridge.js`; it cannot silently choose another model. That bridge requires the operator to set `NE_PSD_QUALIFIED_RUNTIME_BRIDGE_MODULE` to an absolute, regular, non-symlink installed module implementing the trusted adapter. This is executable operator-controlled code, not a JSON report or automatic model fallback. Without the module, the CLI writes a blocked report. The current local transport has no live wire protocol, and the requested Qwen3.8-27B artifact has not been verified. A Mac probe uses `--expected-platform darwin` and a different report name; it cannot satisfy the Windows release gate. The CLI does not start Photoshop, render, mutate documents, or create scheduled work.

An artifactVerified candidate may run a qualification-only trial before `runtimeQualified` is earned. It is never added to the selectable production registry by the CLI. The bridge must probe actual runtime identity, artifact and chat-template hashes, tokenizer, build, context/output limits, JSON schema, image input, qualified transport/sampling, and evidence references. Corpus calls follow only after those probes and exact profile/qualification/resource locks agree. The report always states `productionSelectable: false`; a passing trial needs separate trusted record admission and integration review.

The resource observer starts before corpus invocation and records at least two dated samples during its run: actual OS/architecture, physical and available/used system memory, model/Photoshop/desktop PID and RSS, GPU kind/offload/free/used, Windows commit/pagefile pressure, and the largest representative qualified PSD/PSB workload. The workload includes digest/bytes and positive evidence that Photoshop document is open, desktop is active, and model is loaded. Runtime locks include both exact qualification digests, selected profiles, artifact/runtime/chat template, prompt/policy, context/cache/output settings. The observer must measure through the serial corpus with the intended residency or explicit unload/load strategy. Host-partial and synthetic samples block qualification. A flag or manually copied number is not process/workload evidence.

The capacity gate requires available RAM at every observed sample of at least `max(8 GiB, 15% physical RAM)`. A discrete GPU needs free VRAM of at least `max(2 GiB, 10% total VRAM)`. Unified GPU memory is recorded but not added to system RAM again. Windows release evidence requires commit/pagefile observations, no paging thrash, positive process and workload measurements, all corpus calls within configured deadline, and warm p95 below 80% of that deadline. These are conservative project gates, not vendor guarantees. Actual Q4/Q6/Q8 weights and Photoshop co-residency must be measured; the parameter arithmetic alone cannot qualify hardware.

Blocked reports distinguish platform mismatch, unverified artifact, missing live bridge, probe mismatch, corpus failure, and missing resource evidence. Failed/synthetic trial reports do not qualify production publication.

# Fixed synthetic acceptance corpus

`tests/intelligence/fixtures/acceptance-corpus.json` freezes 64 cases: 12 planner grounding, 20 runtime review, 12 adversarial JSON, 12 failure/context/capability, and 8 diagnostic/visual. Every row points to a repository-relative descriptor under `tests/intelligence/fixtures/acceptance/cases/`. The row carries expected structured status, required and prohibited JSON paths, failure code, and an evidence requirement. The descriptor carries the actual adapter input and any fault seed. Expected answers are not supplied to the candidate model.

The 27 reviewer descriptors include complete synthetic source, three references, three outputs, six detail crops, `RenderEvidence`, a sealed manifest, review policy, JobSpec, and a trusted-state fixture. The images are generated from license-free SVG geometry, decoded to PNG with Sharp 0.35.4. Visible defect cases alter actual pixels: wrong source, missing design region, crop damage, clipping bleed, wrong perspective, missing shadow, changed background, repeated variant, and a narrow edge mark. Good cases include flat color, contain margins, stretch, and a mixed three-variant comparison. The detail crop rectangles, image order, file digests, defect regions, and rubric version are frozen in `docs/intelligence/qualification/visual-corpus-manifest.json`.

Every reviewer descriptor also carries `input.imageQualityPolicy` and `input.colorTraceSelection`. The selected trace is the sealed `traces/tool.json` file containing three artifact-bound sRGB export proofs; `reports/qa.json` records actual `inspectImageQuality` measurements, and `reports/qa-calibration.json` binds the synthetic thresholds and image digests. The positive bundles pass the real deterministic QA function. This calibration is explicitly scoped to these generated pixels and is not backend or production qualification.

The current descriptors declare `foundationContractVersion: 1`. They are synthetic implementation fixtures, not production V2 render evidence. A's additive V2 render contract requires owned-input, template-closure, release, owner-snapshot, and journal-snapshot proof bytes. Production corpus qualification must add and seal those files under the reviewed shared V2 contract. A V1 descriptor must not be cast to V2 or have its missing proofs treated as empty. The independent visual images and expected visible facts remain reusable during migration.

`responseFault.stage: "after-live-model-response"` identifies a host-validation test that mutates a reply after a real model response. Those mutations test strict parsing and binding; they are not evidence of model perception. `preflightFault` identifies a deterministic setup or transport boundary. The runner must record model calls separately and must not invoke a model after a preflight rejection. Visible-defect cases require the actual reviewer to identify the seeded defect in all three repetitions. A fake runner can check corpus mechanics but cannot qualify vision.

FC04–FC06 carry a `budgetRecipe` for the real qualified `counter.countPacket` and selected runtime context limit. The driver varies the planner instruction and output reserve using measured packet counts; an unreachable exact boundary is a fixture setup failure. `syntheticExampleCounts` only documents arithmetic and cannot certify a live tokenizer or context limit.

Run the pinned Node 22 generator without flags to verify frozen corpus and source-image hashes. `--freeze` regenerates files and expected digests and is reserved for an intentional corpus revision before any live evaluation. The fixture test checks every file hash, PNG decode, actual crop pixels, group counts, distinct case inputs, and visible defect pixels. Windows, Photoshop, exact Qwen artifact/runtime, and a qualified vision reviewer remain separate live gates.

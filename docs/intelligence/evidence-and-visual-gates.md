# Evidence and visual gates

The reviewer accepts one sealed V1 bundle for the current job, asset and attempt. It reads every listed regular file under explicit file/count/total limits, rejects symlinks, path collisions, changed bytes and changed trusted attempt state, and retains private byte copies. The supplied render evidence must equal `render-evidence.json`. Three indexed output images, source, three references and three details are required. Image digests, declared dimensions, actual decoded dimensions, format and detail crop pixels are checked before inference.

Deterministic image QA uses an explicitly qualified template/output policy, decoded pixels and three color export proofs inside a sealed trace. The host rejects a failed QA report before model inference. The model receives actual image-channel bytes under recorded image/count/decoded-byte and context limits. A fresh reviewer session returns strict JSON; the host checks current identity, all fifteen mandatory checks, each of the three variant findings, manifest references and verdict consistency. A model pass cannot override failed host evidence. A `revise` recommendation requires first attempt, safe cleanup and a cause-bound coordinator-approved correction.

The `humanPerAsset` path uses a distinct packaged text-only prompt and a trusted, consumed, current attestation bound to the pre-attestation content digest. It does not claim the text reviewer saw pixels. The manual approval must cover this asset's three current outputs.

Synthetic V1 tests establish implementation behavior only. Real publication also requires the V2 owned-input, template-closure and release proofs, owner/journal snapshots, a persisted trusted V2 request reader, qualified Windows/Photoshop render evidence and a qualified visual runtime or actual consumed operator attestation. V2 proof adoption is blocked on the separate shared contract commit approvals recorded in `handoff.md`; no V2 evidence is projected into the V1 schema.

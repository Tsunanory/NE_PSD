# Planner and diagnostic contract

The planner receives one validated inspection, the caller's instruction and fit choice, one selected registry-qualified model, and a fresh transport session. It sends exactly one system and one user message. Before transport, a qualified token adapter counts the complete request and binds its tokenizer, chat template, runtime build, context limit and evidence path to the admitted profile. The host reserves output and safety tokens and checks both model and runtime limits. An unavailable or mismatched counter blocks the call.

The host validates inspection binding, every target/reference/input ID and selector kind, observed document lineage, variants 1/2/3, fit capability, evidence references and output completeness. A proposed configuration requires a complete output. A blocked configuration retains safe selected IDs and explicit fit, with precise unresolved fields; unresolved output dimensions use `output:null`. The shared contract change to permit complete output on an otherwise blocked proposal is tracked in `task-3-dependency-request.md`. No model-provided selector, hash or qualification claim becomes trusted through prose.

The separate diagnostic adapter receives a bound subject, error and evidence request. The host filters a fixed action catalog before inference, then checks every response echo, nested evidence reference, action and status. Retry requires attempt 1, safe cleanup, an allowlisted known cause and a coordinator-owned deterministic correction. The model only recommends an action; it cannot execute it, set retry state, create attempt 3 or issue a publication verdict. Unknown Photoshop state, missing attestation and exhausted attempts block retry.

Filenames, layer names, metadata, tool output and errors remain data, including JSON fragments, fake role tags, Markdown fences, Unicode lookalikes and encoded instructions. The transport cannot acquire tools, history, a different endpoint or another model from that data.
